# Figma 추출/구현 Workflow

Figma 디자인을 코드로 옮기는 2단계 Skill.

## 해결하는 문제

Figma MCP(`get_design_context`)를 직접 호출하면 프레임당 500KB~2MB 응답이 대화 컨텍스트에 쌓인다.
복잡한 디자인은 여러 프레임을 조회해야 하므로, 추출만으로 컨텍스트가 소진되어 구현까지 이어가기 어렵다.

이 Skill은 **추출과 구현을 분리**하여 컨텍스트를 보호한다.

```
/figma-extract                      /figma-implement
┌──────────────────────┐            ┌──────────────────────┐
│ 서브에이전트가           │            │ 메인 에이전트가          │
│ Figma MCP 호출        │            │ 스펙 파일만 읽고         │
│ (500KB~2MB 응답)      │  ──────>   │ 코드 구현               │
│ 스펙 파일로 정제         │  파일시스템   │ Figma MCP 호출 안 함   │
│ 요약만 메인에 반환       │            │                       │
└──────────────────────┘            └──────────────────────┘
```

---

## 사용법

### 1단계: 추출

```
/figma-extract [Figma URL]
```

Figma URL을 주면, 서브에이전트가 디자인을 조회하고 `docs/specs/{기능명}/`에 스펙 파일을 생성한다.

추출 결과로 **자동 검증 요약**과 **사용자 체크리스트**가 함께 제시된다.
체크리스트로 스펙 품질을 확인한 뒤 구현으로 넘어간다.

### 2단계: 구현

```
/figma-implement [기능명]
```

`docs/specs/{기능명}/`의 스펙 파일을 읽고 코드를 생성/수정한다.
구현 완료 시 **스펙-코드 불일치 보고**가 제시된다.

---

## 모드

### 신규 (new)

해당 기능의 코드가 없을 때. Figma 디자인 전체를 스펙으로 기록한다.

### 수정 (update)

해당 기능의 코드가 이미 있을 때. 현재 코드와 Figma 디자인의 **차이점(diff)만** 기록한다.
현재 코드가 base이고, 변경분만 스펙에 남긴다.

---

## 상태 분류: Base / Delta / Independent

하나의 기능에 여러 UI 상태가 있을 때, 전체 트리를 매번 반복하지 않는다.

| 분류            | 기준                                 | 예시                   |
| --------------- | ------------------------------------ | ---------------------- |
| **Base**        | 가장 기본이 되는 상태                | Default 화면           |
| **Delta**       | Base와 구조 대부분 동일, 일부만 다름 | 체크박스 ON, 에러 상태 |
| **Independent** | Base와 완전히 다른 구조              | 모달, 빈 상태          |

Delta 판정 조건:

1. 최상위 레이아웃이 Base와 동일
2. 변경되는 노드가 전체의 20% 이하
3. 변경이 특정 영역에 한정

Delta가 6개 이상이면 관련 Delta끼리 그룹핑하여 파일 수를 줄인다.

## 출력 구조

### 신규 모드

```
docs/specs/{기능명}/
├── index.md          # 조감도: 메타, 상태 목록, 전환 관계, 공통 레이아웃
├── tokens.json       # 디자인 토큰
├── unknowns.md       # 불확실/미확인 항목
├── base.md           # 기본 상태 전체 컴포넌트 트리
├── deltas/           # Base 대비 변경분
│   └── *.md
├── {상태명}.md       # Independent 상태 (전체 트리)
└── components/       # 공유 컴포넌트 스펙
```

### 수정 모드

```
docs/specs/{기능명}/
├── index.md          # 변경 요약, 대상 코드 위치
├── tokens-diff.json  # 변경된 토큰만 (없으면 생략)
├── unknowns.md       # 불확실/미확인 항목
├── changes/          # 현재 코드 대비 변경 스펙
│   └── *.md
└── components/       # 공유 컴포넌트 스펙 (해당 시)
```

## 안전장치

### Blocker 시스템

추출/구현 모두, 아래 상황에서는 작업을 멈추고 보고한다:

- 출력 디렉토리 충돌 (기존 스펙 덮어쓰기 방지)
- 모드 판별 불가 (추측하지 않음)
- 수정 모드에서 대상 코드 경로 미확인
- Figma 응답 부분 수신으로 핵심 상태 누락
- Base 상태 결정 불가

### 토큰 scope 제어

수정 모드에서 토큰 변경이 발견되면 기본적으로 해당 기능 코드에만 적용한다 (`scope: local`).
전역 디자인 시스템 변경이 필요하면 사용자 승인을 먼저 받는다.

### 검증

- 추출 후: 필수 파일 존재, 참조 무결성, placeholder 잔존 여부를 점검
- 구현 후: 스펙 대비 변경/추가/미구현 항목을 보고

## Skill 파일 구조

```
.claude/skills/
├── figma-extract/
│   ├── SKILL.md                         # /figma-extract 진입점
│   ├── figma-extract-rules.md           # 서브에이전트 추출 규칙
│   └── references/
│       ├── failure-handling.md           # 추출 blocker 상세
│       └── validation.md                # 추출 검증 + 사용자 체크리스트
└── figma-implement/
    ├── SKILL.md                         # /figma-implement 진입점
    └── references/
        ├── failure-handling.md           # 구현 blocker 상세
        └── validation.md                # 구현 검증 + 완료 보고 템플릿
```

각 SKILL.md가 핵심 워크플로우를 담고, `references/`는 edge case 처리를 위해 필요 시에만 읽힌다.
