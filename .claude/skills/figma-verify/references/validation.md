# Figma Verify Validation

## 자동 검증 요약

검증 보고를 메인 에이전트에 반환하기 전, 서브에이전트는 아래 항목을 자동으로 점검한다.

### 공통 검증

- 호출한 MCP 도구 목록과 노드 ID가 보고에 명시되어 있는가
- 검증 항목 수 / 일치 / 불일치 카운트가 일치하는가 (총합 검산)
- 표 형식 외 자유 서술이 끼어 있지 않은가
- 일치 항목을 묘사한 문장이 남아 있지 않은가
- `get_design_context`가 fast 모드에서 호출되지 않았는가
- 페이지/프레임 단위 호출이 발생하지 않았는가

### 직접 근거 무결성 (false-positive 차단)

- 모든 in-scope 항목에 항목 성격에 맞는 **직접 근거 1줄**이 보고되어 있는가 (`metadata` / `screenshot` / `variable_defs`)
- "토큰명 일치 = match" 같은 판정이 단독으로 등장하지 않는가
- `get_metadata`가 인스턴스 노드라 children을 반환하지 않은 경우, 시각 판단이 필요한 항목은 **screenshot 보완 검증**이 수행되었는가 (보고에 명시되어야 함)
- scope 힌트가 좁더라도 판단에 직접 영향을 주는 인접 레이아웃 차이(컬럼/행 구분선, 들여쓰기, 정렬)가 함께 점검되었는가 (`layout-adjacent` 분류 사용 흔적)
- screenshot에서 **컬럼 사이 세로 구분선의 유무**가 명시적으로 확인되었는가 (테이블 검증 시 의무)
- screenshot에서 **트리뷰 들여쓰기 시 부모/자식 체크박스 정렬**이 명시적으로 확인되었는가 (트리뷰 검증 시 의무)
- **사용자가 명시한 시각 힌트**(컬럼 구분선/정렬/border 등)에 대해 sub-agent가 식별 못 했다면 `layout-adjacent`로 등재되었는가 (사용자 관찰 우선 룰 — false-negative 차단)

### 호출 한도 검증

- fast 모드: MCP 호출 ≤ 3
- deep 모드: MCP 호출 ≤ 5
- 한도 초과 시 미검증 항목이 명시되어 있는가

### 책임 경계 검증

- 코드를 수정한 흔적이 없는가 (검증 단계는 read-only)
- 스펙 파일을 갱신한 흔적이 없는가 (재추출은 verify의 책임 아님)

### 검증 실패 처리

- 위 항목 중 하나라도 어겼으면 보고 직전에 자가 수정한다
- 자가 수정이 불가능하면 "검증 보고 무결성 위반"으로 표시하고 메인 에이전트 결정에 맡긴다

## 보고 템플릿

서브에이전트는 아래 형식으로 메인에 응답한다. 자유 서술 금지.

```
## Figma 검증 보고

### 기본 정보
- Figma 노드: {URL 또는 노드 ID}
- 검증 모드: fast | deep
- 검증 대상 코드: {파일 경로 목록}
- 관련 스펙: {스펙 디렉토리 또는 "없음"}
- 추출 시점 vs 현재: {스펙 추출 일자, 노드 ID 일치 여부 — "없음"이면 생략}

### MCP 호출 기록 (감사용)
| # | 도구 | 노드 ID | 응답 크기 추정 | 사용 목적 |
| - | --- | --- | --- | --- |
| 1 | get_screenshot | 45015-350239 | ~80KB | 다이얼로그 시각 비교 |
| 2 | get_metadata | 45015-350239 | ~30KB | TabsList 구조, 테이블 row 카운트 |

### 검증 카운트
- 검증 항목: 12
- 일치 (직접 근거 확인): 8
- 불일치: 3
- 확인 필요/placeholder: 1

### 직접 근거 매트릭스 (모든 in-scope 항목 의무)

`metadata`, `screenshot`, `variable_defs` 중 항목 성격에 맞는 직접 근거를 항목당 1줄로 기록한다. 비어 있으면 "검증 안 됨"이며 일치로 처리하지 않는다.

| 항목 | 토큰/스펙 매칭 | 직접 근거 | 최종 판정 |
| --- | --- | --- | --- |
| 다이얼로그 외곽 border | 일치 | screenshot 좌상단 1px 외곽선 4면 모두 확인 | match |
| 행 구분선 (border-t) | 일치 | screenshot에서 row 사이 1px 가로선 모든 행에 확인 | match |
| 탭 children 수 | 일치 | metadata에서 TabsList children 2개 확인 | match |
| 컬럼 사이 세로 구분선 | (스펙에 없음) | screenshot에서 이름/확장자/날짜 컬럼 사이 1px 세로선 확인 — **코드에 누락** | layout-adjacent |
| 트리뷰 들여쓰기 정렬 | (스펙 모호) | screenshot에서 파일 row checkbox가 폴더 row checkbox와 동일 픽셀에 정렬 — 코드는 `pl-8`로 16px 시프트 | layout-adjacent |

### 불일치 항목
| 위치 (file:line) | 디자인 값 | 코드 값 | 분류 | 추정 원인 | 직접 근거 |
| --- | --- | --- | --- | --- | --- |
| tab-import.tsx:36 | 폴더 4개 | 폴더 2개 | discrepancy | 목업 fidelity 누락 | screenshot에서 좌측 폴더 4개 시각 카운트 |
| tab-sync.tsx:24 | 폴더 8개, 날짜 2026-01-20 19:00 | 폴더 3개, 날짜 2024-01-15 | design-updated | 추출 이후 디자인 변경 추정 | screenshot 텍스트 OCR로 날짜 포맷 확인 |
| agent-knowledge-dialog.tsx:50 | 탭 균등 분할 | inline-flex (콘텐츠 너비) | discrepancy | 레이아웃 의도 누락 | screenshot에서 두 탭이 다이얼로그 너비를 50/50 분할 |

### 디자인 업데이트 추정
- 위 표에서 `design-updated`로 분류된 항목이 있으면 `figma-extract` 수정 모드로 스펙 갱신을 권장한다
- 추정 근거: 노드 ID 변경 / 추출 시점 N개월 경과 / 스펙 메타데이터와 응답 차이 등

### 미검증 항목
- (호출 한도 초과 등으로 검증하지 못한 항목 또는 "없음")

### 추가 정밀 검증 권장 (선택)
- 깊은 인터랙션 hint가 필요하다면 deep 모드로 재실행 권장
- 스펙 갱신이 필요하다면 `figma-extract` 수정 모드로 안내
```

## 메인 에이전트의 사용자 보고

서브에이전트의 보고를 받은 메인 에이전트는 사용자에게 다음을 추가로 제공한다:

1. **불일치 표의 파일 경로/라인을 markdown 링크로 변환**
   - 예: `[tab-import.tsx:36](src/.../tab-import.tsx#L36)`
2. **수정 여부 확인 질문**
   - "위 항목들을 수정할까요? `discrepancy` 3건은 즉시 수정 가능, `design-updated` 1건은 스펙 갱신부터 필요합니다"
3. **자동 수정 금지**
   - 사용자가 명시적으로 승인하기 전에는 코드를 바꾸지 않는다

## 사용자 검토 체크리스트

```
## 검증 결과 검토 체크리스트

### 보고 신뢰성
- [ ] MCP 호출 기록의 노드 ID가 의도한 영역과 일치하는가?
- [ ] 검증 항목 수가 합리적인가? (너무 적으면 범위 누락 가능성)

### 분류 적절성
- [ ] `discrepancy`로 분류된 항목이 실제 코드 누락인가?
- [ ] `design-updated`로 분류된 항목이 실제 디자인 변경인가? (스펙과의 비교 결과)
- [ ] `placeholder` 항목이 자산 확정 후 재검증할 수 있게 표시되었는가?

### 후속 작업
- [ ] `discrepancy` → 코드 수정으로 해결할 수 있는가?
- [ ] `design-updated` → `figma-extract` 수정 모드로 스펙부터 갱신할 것인가?
- [ ] 미검증 항목이 있으면 추가 검증을 돌릴지 결정했는가?
```
