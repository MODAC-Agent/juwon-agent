# Figma Extract Failure Handling

## 목적

`figma-extract` 실행 중 blocker가 보일 때의 상세 처리 규칙이다.
메인 에이전트와 서브에이전트가 같은 판단 기준을 공유하도록 한다.

## Blocker 케이스

### 출력 디렉토리 충돌

- 출력 디렉토리가 이미 존재하고, 교체 여부가 프롬프트에 명시되지 않았으면 **덮어쓰지 않는다**
- 기존 파일을 보존한 채 종료하고, "기존 스펙과 충돌"로 보고한다
- 비교용 신규 추출이면 `docs/specs/{기능명}-v2/`처럼 별도 경로 사용을 제안한다

### 모드 불명확

- 신규/수정 모드를 구분할 수 없으면 추측하지 않는다
- 가능한 근거를 정리해 보고하고, 메인 에이전트가 결정하도록 넘긴다

### 수정 모드인데 대상 코드 위치가 불명확

- 프롬프트에 코드 경로가 없거나 경로가 존재하지 않으면 먼저 가능한 파일을 탐색한다
- 그래도 확정할 수 없으면 diff 추출을 진행하지 않고 blocker로 보고한다

### Figma MCP 응답이 너무 크거나 일부만 수신됨

- 페이지 단위 조회가 크면 프레임/섹션 단위로 나눠 재조회한다
- 끝까지 일부 프레임만 확인 가능하면, 확인된 범위만 스펙화하고 미확인 범위를 `unknowns.md`와 완료 보고에 명시한다
- 핵심 상태(Base 후보 등)가 빠졌다면 추출 완료로 간주하지 않는다

### 필수 상태가 없어서 base를 정할 수 없음

- Default 또는 이에 준하는 기본 상태를 찾지 못하면, 임의로 base를 만들지 않는다
- 가장 안정적인 후보를 근거와 함께 제시하고 blocker로 보고한다
